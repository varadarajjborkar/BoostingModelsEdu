The finale

XGBoost, LightGBM, CatBoost: which one?

Same engine inside: gradient boosting with trees. Three personalities on the outside. Here is how to pick one in 30 seconds, and how to tune any of them.

1

Three personalities

If they were people, this is how they would introduce themselves.

XGBoost

"The careful all-rounder"
  • Slope + curve for every split, with λ and γ brakes
  • Learns a default path for missing values
  • Many knobs, huge community, runs everywhere
Watch out: many knobs means more tuning.
signature: level-wise trees + regularized gain

LightGBM

"The speedster"
  • Buckets instead of exact values
  • Leaf-wise growth: the most useful leaf first
  • GOSS + bundling: less work on big data
Watch out: can overfit small data. Limit num_leaves.
signature: histogram + leaf-wise trees

CatBoost

"The category whisperer"
  • Word columns without leaking answers
  • Symmetric trees: steady, fast to predict
  • Very good with default settings
Watch out: training can be slower on big numeric data.
signature: ordered target statistics + symmetric trees

Hood

Under the hood

The shared math, a fair way to compare, and all three libraries in one script.

All three build the same kind of team

$$F_M(x) = F_0 + \nu \sum_{m=1}^{M} h_m(x)$$

Say it: start from a first guess, then add many small trees, each shrunk by the learning rate $\nu$.

All three pick leaf values the same way

$$w_j = -\frac{G_j}{H_j + \lambda}$$

Say it: slopes and curves of the dots in the leaf, with a brake. The differences are which trees they build and how fast, not this formula.

to compare boosters fairly:

  Step 1. Same data, same split
     split once into train / validation / test, and reuse it for everyone

  Step 2. Same rules
     same learning rate (e.g. 0.05), early stopping on the validation part
     similar tree size (depth 6 ≈ 64 leaves ≈ num_leaves 63)

  Step 3. Score on data nobody tuned on
     report the test score once, at the very end

  Step 4. Look beyond the score
     training time, prediction time, how much tuning it needed
# pip install xgboost lightgbm catboost scikit-learn
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.metrics import roc_auc_score
import xgboost as xgb
import lightgbm as lgb
from catboost import CatBoostClassifier

X, y = make_classification(n_samples=20000, n_features=20, n_informative=8, random_state=0)
X_train, X_rest, y_train, y_rest = train_test_split(X, y, test_size=0.4, random_state=0)
X_valid, X_test, y_valid, y_test = train_test_split(X_rest, y_rest, test_size=0.5, random_state=0)

models = {
    "XGBoost": xgb.XGBClassifier(n_estimators=2000, learning_rate=0.05, max_depth=6,
                                 tree_method="hist", early_stopping_rounds=100),
    "LightGBM": lgb.LGBMClassifier(n_estimators=2000, learning_rate=0.05, num_leaves=63, verbose=-1),
    "CatBoost": CatBoostClassifier(iterations=2000, learning_rate=0.05, depth=6,
                                   early_stopping_rounds=100, verbose=0),
}

for name, model in models.items():
    if name == "LightGBM":
        model.fit(X_train, y_train, eval_set=[(X_valid, y_valid)],
                  callbacks=[lgb.early_stopping(100, verbose=False)])
    elif name == "XGBoost":
        model.fit(X_train, y_train, eval_set=[(X_valid, y_valid)], verbose=False)
    else:
        model.fit(X_train, y_train, eval_set=(X_valid, y_valid))
    auc = roc_auc_score(y_test, model.predict_proba(X_test)[:, 1])
    print(f"{name:9}  test AUC = {auc:.4f}")

Remember it

  1. Same engine. Differences: tree shape, speed tricks, word columns.
  2. Word columns → CatBoost. Huge data → LightGBM. All-rounder → XGBoost.
  3. Always: validation data + early stopping. Then tune tree size.
Your data has 20 columns of shop names and brands, and you have little time to tune. First pick?

Word-heavy data plus strong defaults is exactly CatBoost's home ground.

Which one grows trees leaf-wise by default?

LightGBM always splits the most useful leaf next. That is also why num_leaves is its main knob.

Validation error starts rising after 300 trees, while training error keeps falling. What should you do?

Rising validation error means the extra trees are memorizing noise.
